> 문서 상태: 구현 승인 전 설계 기준선

## 1. 결론

현재 화면의 핵심 문제는 색상이나 유리 효과가 아니라 **서로 다른 두 업무를 하나의 고정 폭 세로 패널에 계속 쌓은 정보 구조**다. 장소 탐색, 모임 추천, 카페 검색, 정부 혜택, 데이터 연결 상태가 모두 약 400px 폭의 한 열을 공유하면서 다음 문제가 동시에 생겼다.

- 지도는 화면 상단 일부 높이에서 끝나고 아래에 큰 공백이 남는다.
- 입력 조건이 늘어날수록 결과가 첫 화면 밖으로 밀려난다.
- 검색 실패, 위치 권한 실패, 외부 API 저하가 모두 비슷한 빈 결과처럼 보인다.
- 기능별 상태와 이벤트가 하나의 대형 인라인 스크립트에 결합되어 한 결함이 다른 기능까지 전파된다.
- 정부 혜택처럼 지도가 필요 없는 업무도 지도 레이아웃에 갇혀 카드 폭과 밀도가 무너진다.

따라서 정적 단일 HTML을 더 보수하는 방식은 중단하고, **React + TypeScript + Vite + shadcn/ui 기반의 반응형 지도 탐색 워크스페이스**로 점진 전환한다. 장소 탐색과 정부 혜택을 같은 제품 안에 유지하되 화면 구조는 분리한다.

1. **주변 탐색:** 고정 높이 작업 패널과 전체 높이 지도, 목록·마커 양방향 동기화
2. **정부 혜택:** 지도를 제거한 필터·검색·2~3열 결과 카드 워크스페이스
3. **모바일:** 지도 위 고정 사이드바가 아니라 지도 + 드래그 가능한 결과 시트(bottom sheet)

## 3. 첨부 화면의 시각적 결함 감사

첨부한 1728×1470 화면을 기준으로 한 대략적인 관찰이다.

| 항목 | 관찰 | 사용자 영향 |
|---|---|---|
| 좌측 작업 영역 | 약 420px 폭의 단일 세로 열 | 필터·설명·결과가 계속 아래로 밀림 |
| 지도 영역 | 상단 약 720px 높이에서 종료 | 화면 아래 절반 가까이가 기능 없는 공백이 됨 |
| 모임 조건 | 인원·예산·시간·분위기를 모두 펼쳐 표시 | 검색 전부터 조작 밀도가 과하고 결과 접근이 늦음 |
| 빠른 검색 | 작은 버튼을 2열로 반복 | 중요도 구분이 없고 시선 이동이 많음 |
| 검색 결과 | 입력 블록 아래에만 배치 | 결과를 보려면 긴 스크롤이 필요하고 지도와 동시 비교가 어려움 |
| 정부 혜택 | 좁은 열 안에서 카드 결과를 표시 | 카드 폭은 좁고 세로 공간은 길어져 정보 밀도와 균형이 저하됨 |
| 오류 표현 | “조건 불일치”, “인증 설정”, 빈 결과가 유사한 박스로 표시 | 사용자가 재시도·조건 변경·외부 이동 중 무엇을 해야 하는지 알기 어려움 |

### 4.3 시장 조사 결론

최적의 참조 유형은 전통적인 “관리자 대시보드”가 아니라 **store locator + local discovery + benefit finder**의 결합이다. 장소 탐색은 지도 중심이어야 하지만 정부 혜택은 문서·카드 중심이어야 한다. 두 모드를 같은 레이아웃에 억지로 넣는 것이 현재 공간 낭비의 직접 원인이다.

## 5. 목표 사용자 경험

### 5.1 제품의 한 문장 정의

> 현재 위치와 조건을 한 번만 정하면, 주변에서 지금 할 수 있는 장소 또는 내가 확인할 정부 혜택을 다음 행동과 함께 보여주는 생활 탐색 워크스페이스

### 5.2 데스크톱 — 주변 탐색 모드

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 브랜드 │ [주변 탐색] [정부 혜택] │ 현재 위치/지역 검색 │ 연결 상태 │ 테마   │
├────────┴──────────────────────────┬───────────────────────────────────────────┤
│ 작업 패널 360~400px              │ 전 화면 높이 지도                         │
│ ┌ 빠른 목적 선택 ──────────────┐ │  검색 반경 · 현 위치 · 지도 컨트롤        │
│ │ 점심 · 저녁 · 데이트 · 운동  │ │                                           │
│ └──────────────────────────────┘ │      선택 마커 / 반경 / 결과 클러스터      │
│ [조건 요약 리본] [필터 열기]     │                                           │
│ ─ 결과 12 · 거리순 ───────────── │                                           │
│ 결과 카드 ↔ 마커 동기화          │                                           │
│ 패널 내부만 스크롤                │                                           │
└──────────────────────────────────┴───────────────────────────────────────────┘
```

핵심 규칙:

- 페이지 전체가 아니라 **작업 패널만 스크롤**한다.
- 지도는 `100dvh - header`를 유지해 아래 공백을 만들지 않는다.
- 모임 상세 조건은 기본 접힘 상태로 두고, 선택값은 한 줄 “조건 요약 리본”으로 표시한다.
- 검색 결과를 빈 화면 아래로 추가하지 않고 같은 패널에서 입력 영역을 축소하며 교체한다.
- 결과 카드 선택 시 마커와 지도를 강조하고, 마커 선택 시 해당 카드를 스크롤해 노출한다.

### 5.3 데스크톱 — 정부 혜택 모드

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 브랜드 │ [주변 탐색] [정부 혜택] │ 통합 검색 │ 연결 상태 │ 테마           │
├──────────────────────┬───────────────────────────────────────────────────────┤
│ 조건 필터 280px      │ 맞춤 혜택 24                                         │
│ 생애주기             │ ┌──────────────┐ ┌──────────────┐ ┌──────────────┐ │
│ 대상                 │ │ 혜택 카드     │ │ 혜택 카드     │ │ 혜택 카드     │ │
│ 지역                 │ └──────────────┘ └──────────────┘ └──────────────┘ │
│ [조건 초기화]        │ 인증 저하 시: 공식 정부24에서 계속 찾기 + 재시도     │
└──────────────────────┴───────────────────────────────────────────────────────┘
```

정부 혜택 모드에서는 지도 영역을 제거한다. 카드는 데스크톱 3열, 중간 화면 2열, 모바일 1열로 배치하고 카드 높이를 내용 기준으로 제한한다.

### 5.4 모바일

- 상단 검색과 40~45dvh 지도, 하단 결과 시트로 구성한다.
- 필터는 `Sheet` 또는 `Drawer`로 열고 적용된 조건 수를 배지로 표시한다.
- 결과 시트는 축소·중간·전체 높이 세 상태를 가진다.
- 위치 요청 중에도 헤더와 수동 지역 검색은 사용할 수 있어야 한다.

## 6. 디자인 시스템과 shadcn/ui 적용안

### 6.1 사용할 컴포넌트

- 구조: `Tabs`, `ScrollArea`, `Separator`, `Sheet`, `Drawer`, `Collapsible`
- 입력: `Command`, `Input`, `Button`, `ToggleGroup`, `Select`, `Slider`
- 결과: `Card`, `Badge`, `Skeleton`, `Alert`, `Tooltip`
- 피드백: `Toast`, `Dialog`, 명시적 빈 상태 컴포넌트

shadcn/ui는 완성형 테마 패키지가 아니라 소스 소유형 컴포넌트로 사용한다. 필요한 컴포넌트만 추가하고 직접 수정 가능한 상태로 저장한다.

### 6.2 시각 토큰

| 역할 | 제안 토큰 | 용도 |
|---|---|---|
| 배경 | `--background: #F5F7F3` | 따뜻한 저채도 바탕 |
| 표면 | `--surface: #FFFFFF` | 패널과 카드 |
| 기본 강조 | `--primary: #225A45` | 검색·선택·현 위치 |
| 보조 강조 | `--accent: #F2A65A` | 추천과 주의가 필요한 정보 |
| 텍스트 | `--foreground: #17201C` | 높은 대비 본문 |
| 경계 | `--border: #DDE4DF` | 절제된 구획 |

- 본문은 Pretendard 또는 시스템 한글 산세리프를 사용한다.
- 제목은 굵기와 자간으로 위계를 만들고 과도한 그라데이션·유리 효과는 제거한다.
- 주황색은 모임 기능 전용이 아니라 추천·주의의 의미 토큰으로 통일한다.
- 고유한 시각 요소는 현재 선택 조건을 한 줄로 압축한 **결정 리본(decision ribbon)**이다.

## 7. React·Vite 목표 아키텍처

```text
frontend/
├─ index.html
├─ package.json
├─ vite.config.ts
├─ tsconfig.json
├─ components.json
├─ src/
│  ├─ app/App.tsx
│  ├─ components/ui/              # shadcn/ui 로컬 소스
│  ├─ features/explore/           # 위치·장소·모임·카페
│  ├─ features/benefits/          # 혜택 검색·카드·공식 폴백
│  ├─ features/data-sources/      # 연결 상태
│  ├─ lib/api.ts                  # 백엔드 계약과 오류 정규화
│  ├─ lib/kakao-map.ts            # Kakao SDK 격리 어댑터
│  ├─ hooks/                      # 위치·요청 취소·반응형 상태
│  └─ test/                       # Vitest 계약·컴포넌트 테스트
├─ public/index.html              # 전환 완료 전 레거시 보존
└─ test/                          # 브라우저 MIA 결함 주입
```

Vite는 `publicDir: false`로 시작해 기존 `frontend/public/index.html`을 복사하거나 덮어쓰지 않는다. 새 앱 검증이 끝난 뒤에만 백엔드 정적 경로를 `frontend/dist`로 전환하며, 안정화 기간에는 레거시 정적 경로를 명시적 폴백으로 유지한다.

### 7.1 상태 경계

- `mode`: `explore | benefits`
- `location`: `idle | requesting | resolved | denied | unavailable | timeout`
- `mapSdk`: `loading | ready | failed`
- `request`: 요청별 `idle | loading | success | empty | degraded | error`
- `selection`: 선택한 결과 ID 하나만 저장하고 카드와 마커가 공유한다.
- 파생 값(결과 수, 필터 요약, 거리순)은 별도 상태로 복제하지 않고 렌더 시 계산한다.
- 검색 요청마다 `AbortController` 또는 요청 세대 ID를 사용해 오래된 응답이 최신 화면을 덮지 못하게 한다.

## 8. API와 인증키 UX 원칙

1. `/api/data-sources`를 공개 프론트 계약으로 사용하고 기존 별칭은 백엔드 호환용으로만 유지한다.
2. 모든 목록 응답은 `{ items: [] }` 형태를 보장하고, 오류는 `code`, `message`, `retryable`, `fallbackUrl`로 정규화한다.
3. 지도 SDK에 필요한 브라우저용 앱 설정과 서버 비밀키를 구분한다. 사용자가 화면에서 새 키를 반복 입력하게 하지 않는다.
4. 서버 인증이 없는 혜택 API는 “앱 전체 실패”가 아니라 `degraded` 상태로 처리한다.
5. 혜택 데이터가 없으면 “API키를 확인하세요”만 표시하지 않고 다음 세 행동을 제공한다.
   - 공식 정부24에서 계속 찾기
   - 조건을 바꾸기
   - 연결 상태 확인 후 재시도
6. 오류 응답과 로그에 키·토큰·내부 설정값을 포함하지 않는다.

## 9. MIA 백신형 결함 주입 계획

### 9.1 변이 테스트 행렬

| 주입 결함 | 기대 화면 | 통과 조건 |
|---|---|---|
| 위치 권한 거부 | 수동 지역 선택 안내 | 로딩이 종료되고 지역 선택 가능 |
| 위치 응답 무한 대기 | 제한 시간 후 timeout | 검색 UI가 잠기지 않음 |
| 위치 좌표 범위 오류 | 안전한 기본 지역 또는 재선택 | 지도 예외·백지 화면 없음 |
| Kakao SDK 로드 실패 | 지도 대체 패널 + 목록 검색 안내 | 장소 검색 경로가 명확히 저하됨 |
| 장소 0건 | 조건별 빈 상태 | 오류와 0건을 구분 |
| 카페 API 503 | 지도 장소 검색 폴백 | 실제 장소 결과 또는 폴백 설명 표시 |
| 혜택 API 인증 없음 | `degraded` 혜택 상태 | 원시 인증 오류 대신 공식 경로 제공 |
| API JSON 형식 변이 | 계약 오류 상태 | 렌더 중단 없이 재시도 제공 |
| 10초 지연 | 스켈레톤 + 취소/재시도 | 중복 요청과 무한 스피너 없음 |
| 오래된 요청이 늦게 도착 | 최신 요청만 반영 | 선택 조건과 결과 불일치 없음 |
| 320px 모바일 | 지도 + 결과 시트 | 가로 스크롤·가려진 버튼 없음 |
| 키보드만 사용 | 포커스 순서와 Escape 복귀 | 모든 핵심 행동 수행 가능 |
| 긴 장소명·혜택명 | 2~3줄 제한과 상세보기 | 카드 높이 폭주 없음 |

### 9.2 테스트 계층

1. **계약 테스트:** API 경로, `items` 배열, 오류 정규화
2. **컴포넌트 테스트:** 위치 상태, 빈 결과, 저하 상태, 오래된 요청 차단
3. **브라우저 MIA 테스트:** SDK·위치·fetch를 변이시켜 실제 화면 열기
4. **반응형 시각 감사:** 320, 390, 768, 1280, 1728px 스크린샷 비교
5. **실서비스 스모크:** 공개 Render URL에서만 SDK 도메인·네트워크 통합 확인

## 10. 단계별 구현 계획

### 단계 0 — 기준선 동결

- 기존 변경 파일 소유권을 분리한다.
- 현재 백엔드 16개 테스트와 기존 프론트 MIA 테스트를 다시 실행한다.
- 첨부 화면을 1728px 회귀 기준으로 보존한다.

### 단계 1 — 병렬 React 셸

- 기존 정적 페이지를 수정하지 않고 `frontend/src`에 새 셸을 만든다.
- 주변 탐색과 정부 혜택 라우팅, 디자인 토큰, 반응형 골격을 먼저 구현한다.
- Mock 데이터로 컴포넌트와 공간 배치를 검증한다.

### 단계 2 — 기능 어댑터 이식

- 위치, Kakao 지도, 장소, 카페, 혜택, 데이터 소스 상태를 각각 훅·서비스로 분리한다.
- 검색 결과와 마커 선택을 단일 selection 상태로 연결한다.
- 기존 API 계약을 유지하고 새 프론트 전용 백엔드 로직을 만들지 않는다.

### 단계 3 — 실패 주입 치료

- 9장의 변이 행렬을 자동화한다.
- 각 실패를 로딩·빈 결과·저하·오류 상태 중 하나로 분류한다.
- 사용자가 취할 수 있는 다음 행동이 없는 오류 메시지를 금지한다.

### 단계 4 — 정적 제공 전환

- Vite 프로덕션 빌드가 0으로 종료된 뒤에만 백엔드 정적 경로를 `frontend/dist`로 전환한다.
- Render build command에 프론트 설치·빌드를 추가한다.
- 이 단계는 Render 설정 변경이므로 별도 승인 후 진행한다.

### 단계 5 — 공개 런타임 검증

- `/`, `/api/data-sources`, `/api/benefits?limit=5`, `/api/cafes?limit=5`를 확인한다.
- 실제 위치 권한, 지도 SDK, 결과 카드·마커 동기화, 모바일 시트를 확인한다.
- 공개 URL 검증 전까지 `runtime_verified = false`, `release = blocked`를 유지한다.

## 11. 패키지 설치 승인 경계

예상 설치 목적은 React/Vite 빌드, shadcn/ui의 로컬 컴포넌트 기반, 단위 테스트 환경 마련이다.

- 런타임: `react`, `react-dom`, `lucide-react`, 필요한 Radix UI 패키지, `class-variance-authority`, `clsx`, `tailwind-merge`
- 개발: `vite`, `typescript`, `@vitejs/plugin-react`, React 타입, Tailwind Vite 플러그인, `vitest`, Testing Library, `jsdom`
- 영향: `frontend/package.json`, `frontend/package-lock.json`, 로컬 `frontend/node_modules` 생성, Render 빌드 절차 변경 예정
- 롤백: 신규 React 파일과 프론트 lockfile을 제거하고 백엔드 정적 경로를 기존 `frontend/public`으로 유지

설치 전 정확한 명령과 대상 경로를 제시하고 승인을 받아야 한다. 이번 보고서 작성 단계에서는 패키지를 설치하지 않는다.

## 12. 완료 기준

### 기능

- 현재 위치 성공·거부·시간 초과 모두 종료 상태를 가진다.
- 동네 모임, 점심/저녁, 데이트, 헬스장, 산책로, 카페, 맛집, 병원·약국이 결과 또는 행동 가능한 실패 상태를 제공한다.
- 정부 혜택은 데이터가 없어도 공식 검색으로 이어지고 원시 인증 안내를 노출하지 않는다.

### 레이아웃

- 1280px 이상에서 지도 아래 기능 없는 문서 공백이 없다.
- 주변 탐색의 지도 높이는 헤더를 제외한 전체 뷰포트를 사용한다.
- 결과는 검색 조건과 같은 뷰포트에서 확인할 수 있다.
- 혜택 카드는 3/2/1열 반응형이며 동일 정보 수준의 카드 높이 편차를 제한한다.
- 320px에서 가로 스크롤이 발생하지 않는다.

### 품질

- 백엔드 전체 테스트, 프론트 단위 테스트, TypeScript 검사, Vite 빌드가 모두 0으로 종료된다.
- MIA 결함 주입 브라우저 테스트가 모두 통과한다.
- 접근성 이름, 키보드 포커스, 대비, reduced-motion을 검사한다.
- 응답·브라우저 콘솔·서버 로그에 인증 정보가 노출되지 않는다.

## 13. 위험과 의사결정

| 위험 | 대응 |
|---|---|
| 한 번에 전체 교체해 기존 기능 회귀 | 레거시와 React 앱을 병렬 유지한 뒤 정적 경로만 마지막에 전환 |
| UI 라이브러리 도입이 번들 비대화 | shadcn 컴포넌트와 아이콘을 필요한 경로에서만 직접 import |

## 14. 권고 결정

**React + TypeScript + Vite + shadcn/ui 전환을 승인하되, “기존 화면 즉시 삭제” 방식은 승인하지 않는다.** 새 앱을 병렬로 만들고 MIA 결함 주입을 통과한 뒤 백엔드 정적 제공 경로를 전환하는 두 단계 전략이 가장 안전하다.

첫 구현 단위는 다음으로 제한한다.

1. 반응형 App Shell
2. 주변 탐색/정부 혜택 분리
3. 위치 상태 머신
4. 결과 목록·지도 선택 계약
5. 로딩·빈 결과·저하·오류 컴포넌트

이 단위가 통과한 후 세부 추천 기능을 차례로 이식한다. 이렇게 해야 “화면은 바뀌었지만 작동하는 것이 없다”는 현재 실패를 반복하지 않는다.
